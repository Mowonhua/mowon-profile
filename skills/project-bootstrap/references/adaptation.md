# 项目适配规则

## 项目事实

优先读取现有规则、项目简介、发布契约和构建入口。语言、框架、目录布局与版本号是线索，不能单独证明兼容承诺或测试能力。

## 全局与项目范围

生成项目规则前，读取全局提示词。核对当前 harness 的全局文件或已注入的全局指令。源文件无法读取时，在交付中说明核对范围。

按语义比较全局与项目规则。全局已声明的约束应从项目根和子目录的 `AGENTS.md` 中省去。

项目文件只保留具体路径、命令、模块边界、验证环境与项目例外。一个条目混合全局约束和项目内容时，保留项目增量，删除重复部分。用户明确指定的项目覆盖只描述覆盖范围和条件。

必需章节没有项目增量时，可写“暂无项目级补充约束。”；可选章节没有增量时删除。章节要求不能成为复制全局规则的理由。

## 模板变量

| 变量 | 填写依据 |
|---|---|
| 项目摘要 | 项目名称、用途和实际技术栈，用一段说明 |
| 专项读取入口 | 现有架构、设计或维护入口及触发条件；只补充固定入口未覆盖的专项，没有新增专项时删除变量段 |
| 兼容政策 | 下方发布阶段规则 |
| 项目原则与领域边界 | 项目确认的设计取舍、模块职责和依赖约束 |
| 格式与产物约定 | 已有格式工具、生成文件、配置和运行产物位置 |
| 命令清单 | 已存在的入口、执行目录、环境与平台条件 |
| 项目测试与验证约定 | 测试入口、执行顺序、环境和共享资源等项目约束 |
| 项目专项约定 | 已确认的专属规则；不适用时删除整个可选章节 |

必需章节应保留。可选章节只有存在项目事实时才保留。生成文件应清除全部 `{{变量}}`。

## 不兼容声明

发布阶段未知时，先完成其他初始化，然后询问用户当前阶段以及是否兼容。

已确认处于首次稳定发布前，且没有既有兼容承诺时，可使用以下文本：

> 首个稳定版本发布前，优先建立正确、清晰的结构。对当前工作所需的设计修正，更新接口及其调用方、测试和文档，不保留内部旧接口或旧持久化格式的兼容层，不做迁移和接口版本化。格式变化时明确拒绝不支持的数据，并提供针对已识别旧文件的清理指令。进入稳定发布阶段时应移除本节。

已有稳定或对外兼容承诺时，不写本节。

## 命令与验证环境

命令从构建配置、包脚本、测试入口或项目说明提取。注明工作目录和前置环境。读取配置只能确认入口存在，不能证明命令已经执行成功。

| 命令类别 | 提取内容 |
|---|---|
| 环境准备 | 运行环境、依赖安装和环境初始化入口 |
| 开发运行 | 应用、开发服务或命令行工具的启动入口 |
| 构建 | 调试、发布等现有构建目标及产物位置 |
| 代码检查 | 格式化、静态分析、类型与规范检查入口 |
| 测试 | 定向与完整测试入口，执行条件和报告位置 |
| 生成与交付 | 代码生成、打包、产物检查及已有交付入口 |
| 清理产物 | 已定义的清理入口及作用范围 |

仅填写项目已有且适用的类别。缺少入口时向用户说明缺项，避免按技术栈猜测命令。每条命令标明用途、执行目录、环境条件和作用范围。

将查明的验证环境、执行顺序和共享资源约束写入根 `AGENTS.md` 的测试或项目专项章节。

## 文档与工作资料配置

使用以下素材生成项目配置。已有规则拥有者时合并到原位置，并修正项目入口的相对链接。

| 生成对象 | 初始化时配置的内容 |
|---|---|
| [根 AGENTS.md](../assets/AGENTS.template.md) | 项目事实，以及开头集中配置的专项、文档与决策读取条件 |
| [文档与资料规则](../assets/docs-AGENTS.template.md) | 资料路径、Git 策略、术语格式、文档维护流程、文字语义与独立可读检查 |
| [决策规则](../assets/notes-AGENTS.template.md) | 记录门槛、格式、状态、取代与归档，以及记录文字与证据的维护规则 |
| [决策维护 Skill](../assets/maintain-agent-notes/SKILL.md) | 同一主题记录的证据核对、处置、引用维护与结果报告流程 |
| [简化审查 Skill](../assets/find-simplifications/SKILL.md) | 生产路径、维护义务、保留理由、完整成本与候选验收的调查流程 |

默认资料布局以文档与资料规则素材为准。根据项目已有目录或工单系统调整后，在根入口和文档规则中写入同一实际位置。

按配置后的 Git 策略增补忽略规则。核对长期规则、项目 Skill、术语表和需要随源码交付的规格未被忽略；本地工作材料沿用项目忽略范围。

### 安装项目 Skill

安装前检查同名目录和同职能 Skill。已存在时，按[已有维护 Skill 接入](existing-projects.md#已有维护-skill-接入)合并。

没有既有同职能 Skill 时，按下表复制完整目录。项目内安装实际文件，使配置能随 Git checkout 和 worktree 使用。

| 安装素材 | 默认目标 |
|---|---|
| `assets/maintain-agent-notes/` | `.agents/skills/maintain-agent-notes/` |
| `assets/find-simplifications/` | `.agents/skills/find-simplifications/` |

按项目规则与流程的实际位置修正 Skill 的相对链接。同步修正根入口和子目录规则中的调用链接。素材中的链接以安装后的项目路径为准。

安装完成后，检查 `SKILL.md` 的 frontmatter、目录名与链接，并确认项目 Skill 未被忽略。

格式工具、CI、编辑器与 harness 配置沿用既有文件。新增配置只覆盖用户请求的用途。
