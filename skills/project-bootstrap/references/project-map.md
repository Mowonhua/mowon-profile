# 项目地图

## 用途

初始化时把实际探索的结果写入 `AGENTS.md` 的项目地图，让后续 Agent 不必重新遍历目录就能判断代码归属、读取顺序和概念的所在位置。

## 内容与边界

- 每个目录或模块占一行，列为 `目录或模块`、`职责`、`核心概念`。
- 职责写明该位置负责的行为，一句话完成；一句话说不清时指向该位置的入口文件或文档，不堆叠细节。
- 只收录稳定的关键位置。配置文件、生成产物、临时目录和测试夹具不入表；频繁变动的内部实现只写到所在模块。
- 写到顶层与二级位置为止。更细的职责由子目录 `AGENTS.md` 或架构说明承担，地图不展开。
- 核心概念只写规范名称与一句话含义，完整定义保持在项目的术语表中。
- 模块边界、依赖关系与设计理由由架构说明拥有，地图不复制。
- 行内容来自实际探索。职责或概念无法从入口、路由、导出、模块声明或现有说明证实时不写，也不按名称推测。

## 空白或信息不足的项目

没有源码、只有脚手架或文件很少时，先与用户讨论预期地图：列出计划收录的目录或模块、各自主责和已知概念，请用户确认、补充或删减，确认后再写入表格。

用户不想现在设计时，在该章节保留占位说明，直接复制：

> 地图尚未建立。出现首个功能模块、新增顶层目录或改动跨越多个模块时，读取实际结构与入口，与用户确认后按 `目录或模块`、`职责`、`核心概念` 三列建表并替换本段；补全前先读源码判断归属。

## 已有等效章节

已有“目录说明”“架构概览”等语义相同的章节时，就地补齐为唯一地图，不并列建表；改名章节时修复入站链接。地图与代码或架构说明冲突时，核对实际结构，修正过期内容。
