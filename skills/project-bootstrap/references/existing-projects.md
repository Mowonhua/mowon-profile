# 已有项目接入

## 合并项目规则

根 `AGENTS.md` 已存在时，就地补齐必需章节。按[全局与项目范围](adaptation.md#全局与项目范围)删除重复约束，保留项目命令、边界、兼容承诺和明确的项目覆盖。

混合条目只保留项目增量。测试顺序、真实运行环境、共享资源锁和远程隔离是项目约束，不能因同段含有全局测试原则而一起删除。指向已自动加载的全局规则的逐条入口可省去。

已有章节使用不同名称但语义一致时，可统一为模板的必需名称，并修复入站锚点。已存在有效文档规则或决策库时，复用其路径。

首次接入只修改协作配置与入口。全部历史记录迁移只在用户请求包含这项工作时执行。

## 已有维护 Skill 接入

安装前检查项目内同名目录，以及项目规则引用的现有决策维护和简化审查 Skill。完整读取候选 Skill 和它实际使用的资源，核对其维护范围。

已有同职能 Skill 时，优先合并到原路径。保留项目有效的流程、检查入口、元数据和调用方式，补齐素材中的分支。规则条款统一引用所属项目规则。

旧工作流的状态、目录移动或冻结步骤与新规则冲突时，按新规则改写工作流。历史档案仍遵守其原冻结规则。

将项目规则中的调用入口指向合并后的 Skill。它对规则的链接应指向唯一权威文件。核对旧入口和工作流引用的资源，确保每种职能只有一个生效的工作流。

同名目录承担其他职责时，保留原目录，为新 Skill 选择不同名称。同步修改目录名、frontmatter 的 `name` 和维护入口。

## 对齐旧决策机制

先修改创建门槛与短格式，再修正状态语义。取消所有非平凡改动都要写 Note 的统一要求，改为按保存位置和未来价值选择。

决策规则统一放在 `.agents/notes/AGENTS.md`。旧规则使用其他文件名时，迁移规则并同步修正可编辑的引用方；冻结历史引用按项目的封存规则处理。

旧 `implemented` 记录只有确认已采纳后才对应 `accepted`。保留其交付事实与验证边界。旧 `proposed` 可能已经被采纳或部分落实，应按证据核对，不只翻译状态字段。

新的固定路径规则只适用于新记录。旧记录可保留地址；状态以字段为准，旧目录名只表示原有布局。状态变化不要求移动文件。

## 全库迁移

用户已授权迁移整个旧库时，逐条核对以下内容：

1. **确定拥有者。** 核对决定、适用条件、当前契约与独有理由。
2. **确定去向。** 选择保留、就地迁移、合并、取代、归档或删除。
3. **迁移有效内容。** 保存独有约束、真实备选、放弃的能力和验证缺口。
4. **修复引用。** 搜索所有入站链接，修正可编辑引用方。
5. **核对完整性。** 每份旧记录应有去向和理由；必要内容应在新拥有者中可读。

迁移清单是本次任务证据，可存放在 `.scratch/reports/`。它不成为新的决策权威或常驻索引。

## 冻结档案与冲突

旧系统已封存的文件保持原文、地址与格式。活跃记录被冻结档案引用时，保留该目标地址。可在目标增加当前拥有者链接，避免改写冻结引用方。

已采纳决定和当前契约冲突时，说明冲突范围，核对授权与实际行为。能证实文档过期时修正事实；核心选择仍未确定时保留待决状态。

迁移分类与格式检查按新生成的项目决策规则执行。
