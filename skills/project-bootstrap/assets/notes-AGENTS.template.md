# AGENTS.md — 决策记录规则

## 用途

Agent Note 是独立的长期决策记录。它保存已有代码、测试和契约不能解释的理由。Agent 按本规则选择、创建和读取；文件存在不保证所有聊天决定已保存。

其他资料的归属与写作要求见[文档与资料规则](../../docs/AGENTS.md)。

创建、修改、评审或整理 Agent Note 时，使用[维护工作流](../skills/maintain-agent-notes/SKILL.md)。

## 独立记录的门槛

以下三个条件同时成立时，创建或更新独立记录：

1. 改变决定需要更换依赖、重写多个调用方、变更持久数据或重做已确认的验收。
2. 维护者只看当前代码与契约，会合理质疑这个选择。
3. 决定来自真实方案的权衡，且理由尚未在其他拥有者处完整保存。

一句话足够说明背景、决定与原因时，正文可只保留一句话。

## 路径与格式

新记录存放在 `decisions/YYYY-MM-DD-topic.md`。日期是首次提出的日期。主题应能区分具体决定；文件路径在状态变化时保持固定。

既有记录可保留旧地址。状态以字段为准，旧目录名只表示原有布局。

每份记录使用标题、`Status:`、`Scope:` 和一段背景、决定、原因。`Scope:` 写受影响的领域、模块或公开契约名称。正文使用简体中文。

```markdown
# 决策标题

Status: accepted
Scope: 适用领域或模块

一至三句话，说明背景、决定与原因。

Authority: [当前契约](相对路径)
Execution: [执行材料](相对路径)
```

`Status:` 根据决定的实际状态填写。`Authority:` 可链接当前契约，没有对应契约时省去该行。已采纳但未实现的记录，应使用 `Execution:` 链接执行材料，并明确说明目标尚未交付；已经落实时可省去该行。两个引用字段使用 Markdown 链接。

备选方案、后果、验证边界和重新考虑条件只在有维护价值时增加。真实备选方案如未记录，应说明证据缺失，避免补造讨论。

## 记录文字与证据

记录应在不读取聊天或评审线程时仍可理解。引用使用可解析的名称与链接；会话编号、评审轮次和个人背书不能代替决定来源或理由。

裁剪记录时，保留原文中仍有效的适用条件、独有理由、真实备选、后果、验证证据和覆盖缺口。历史事件与否决理由按记录用途保留，删除叙述不能改变选择的含义。

目标与交付的区别按[决策状态](#决策状态)核对。执行清单引用对应执行材料，独立记录只保留解释决定所需的内容。

本节适用于可编辑记录。封存档案按[整理与归档](#整理与归档)维护。

## 决策状态

| Status | 含义 |
|---|---|
| `proposed` | 等待采纳的提议 |
| `accepted` | 已采纳的决定 |
| `rejected` | 在记录的条件下被明确否决 |
| `withdrawn` | 尚未采纳的提议被撤回 |
| `superseded` | 决定已被新决定取代 |

`accepted` 只表示已采纳，不证明决定已实现或验证已通过。记录中的交付声明应指向对应执行证据。

用户明确采纳，或 Agent 在授权任务内选定方案后，才使用 `accepted`。Agent 的待讨论提议使用 `proposed`。未实现的决定应注明目标尚未交付。

`proposed` 可转为 `accepted`、`rejected` 或 `withdrawn`。已采纳决定的实质内容被撤销或替换时，应另写撤销或替换决定。

读取 `rejected` 时核对否决条件。否决结论只在这些条件下成立。保留记录时，写清值得重新讨论的条件。

## 更新与取代

先搜索同一主题的拥有者，再决定更新还是新增。同一决定的事实链接可原地修正。核心选择或理由改变时，应创建新记录。

新记录使用 `Supersedes:` 指向旧记录。旧记录可编辑时，使用 `Superseded by:` 指向新记录。新决定被采纳后，可编辑的旧决定才转为 `superseded`。

旧记录已冻结时，新记录单向链接旧记录并说明取代范围。冻结目标保持原文、地址和状态；取代关系以新记录为准。

部分取代时，写清被替代的范围。旧记录保留仍有效的决定，不把整份记录标为失效。可编辑记录通过双方链接说明各自拥有的内容；冻结目标沿用上方的单向链接规则。

## 读取与维护检查

审查或修改记录前，对照其关联契约和执行证据。设计工作可读取对应 `proposed`。涉及旧备选方案时再读取 `rejected`。归档和已取代记录只用于理解历史。

记录维护完成后核对以下事项：

- 记录已区分用户提议、明确采纳与工程自主选择。
- 记录中的目标、理由和交付声明与关联证据一致。
- 新旧记录的取代范围和引用关系完整。
- 本次维护涉及的记录事实与可编辑入站链接已修正。

首版通过领域词、相对链接和文本搜索定位。只有定位成本已经影响任务时，才生成只含路径、标题、状态和范围的查询视图。

## 整理与归档

按未来价值逐条判断，避免用字数、年龄或目标数量筛选。先把独有约束、理由、放弃的能力和验证边界迁到拥有者，再合并或删除无独有内容的活跃记录。

仍影响未来变更的理由保持可读。只有尚有历史价值且不再指导当前工作的记录才封存。无历史价值的重复记录在修复引用后移除。

已被取代或关闭的历史记录可留在原路径。在 `Status:` 下增加 `Archived: YYYY-MM-DD` 后冻结正文；归档不改变决定本身的状态。活跃且仍指导工作的决定保持未归档。

封存后保留原文与地址。新的事实写入当前拥有者。旧系统已冻结的档案沿用原冻结规则，不为统一格式而修改。

冻结档案引用活跃文件时，该目标地址应保留。整理目标前检查冻结入站引用；可编辑引用方可改指当前拥有者。

## 验证范围

机械检查可确认记录状态、字段、链接和取代关系的结构。内容核对负责确认决定来源、真实备选方案、记录遗漏、重复和冲突。

普通任务只核对受影响的记录。迁移整个旧决策库时，才逐条登记每份记录的去向和理由。
