# 维护 Agent Notes

依据[项目决策规则](../../notes/AGENTS.md)维护决策记录。记录门槛、格式、状态与冻结条件以该文件为准。

## 确定范围

先读取项目决策规则和目标目录的适用指令。规则缺失时报告缺项，待规则明确后再修改记录。

创建或修改记录时，检查同一决定、机制和被否决方案的活跃记录。审计指定领域时，覆盖该领域的记录；全库审计时，逐条登记全部记录。

审计或评审请求输出发现与处置清单。创建、修改、整理或归档请求执行任务范围内的维护。

## 维护流程

1. **定位记录。** 根据主题、领域词和引用找到范围内的记录。
   记录每份候选的路径、状态、归档标记及当前拥有者。
2. **核对证据。** 对照当前契约、代码、配置、执行证据和新决定。
   区分已采纳的选择、目标行为和已验证的交付。
3. **判断去向。** 按项目规则选择保留、更新、合并、取代、删除或归档。
   为每项处置指出依据；证据不足的项列为待决。
4. **执行维护。** 创建、修改、整理或归档任务按下方分支完成已授权的处置。
   每份记录应有明确去向，独有内容应有可读的拥有者。
5. **核对结果。** 检查变更后的记录和可编辑入站引用。
   使用项目已有的定向检查入口；检查结论应区分结构与内容。

### 创建与取代

草拟新记录前，按项目规则确认独立记录的必要性。没有达到门槛的内容，返回其所属契约或执行材料。

写入新记录时，同步确认它对旧记录的全部或部分取代。核心选择尚待采纳时，按项目状态规则保留旧决定的效力。存在独立理由或部分有效内容时，标明各自范围。

本次任务内完成已确认的取代关系与引用维护。已知关联记录的处置不能留给未安排的全库审计。

### 整理与归档

逐条检查独有理由、真实备选、放弃的能力和验证缺口。合并或删除前，确认这些内容已在保留的拥有者中可读。

检查否决记录时，核对原否决条件是否仍成立，以及该方案是否仍可能被再次采用。用这些证据判断记录的未来价值，再应用项目保留规则。

执行归档前，检查项目冻结要求和入站引用。已有冻结记录及其引用目标按项目规则处理。

### 验证与交付

结构检查覆盖可编辑记录的字段、路径、链接与取代关系。内容检查覆盖决定来源、证据、独有理由和冲突。归档操作按项目冻结规则核对。仅检查本次任务涉及的记录与引用。

报告已执行的新增、更新、保留、合并、取代、删除和归档，以及待决项的缺失证据。批量审计逐条给出去向与理由。报告实际完成的验证及无法确认的内容。
