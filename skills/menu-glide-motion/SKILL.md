# 丝滑菜单高亮跟随

## 目标

每个菜单面板只放一块高亮背景层，所有条目共用它，下文称共享层。共享层在条目之间快速移动，可中途改道。动效只服务交互反馈：先保证交互语义正确，再调整观感。

## 工作流程

1. **查清宿主约束。** 记录菜单使用的框架或原生控件、焦点管理、滚动容器、动态内容、面板入场缩放和可访问性要求。沿用项目已有的设计 Token、主题和 API。修复任务先定位现象对应的根因：逐行背景、逐事件测量布局、整树重渲染、滚动补动画。完成标准：每项约束有结论，或已标记为不适用。
2. **分开四种状态。** 区分指针指向、键盘焦点、选中或勾选、禁用。四者各自持有状态，不合并为一个变量。键盘导航、ARIA、typeahead 和选择回调由现有菜单组件负责。
3. **一个面板一层。** 每个面板放一块绝对定位的共享层，加 `pointer-events: none` 和 `aria-hidden="true"`，层级压在条目内容之下。子菜单是独立面板，各自维护一层。条目自身不画指针背景。
4. **用几何位置驱动图层。** 读目标条目的可见矩形，写入共享层的 `translate3d(...)`。宽高直接赋值，过渡属性限于 `transform` 和 `opacity`。裁剪、嵌套滚动和缩放的换算见 [实现指引](references/implementation.md)。
5. **在面板上算最近条目。** 监听面板的 `pointermove`，按纵向距离取最近的条目。指针落在留白、分割线或 padding 上时保持当前指向。非选项内容显式跳过，禁用项不获得高亮。
6. **合帧并改道。** 用 `requestAnimationFrame` 合帧：一帧内的多次输入合并为一次位置计算，只消费最新坐标。目标变化时给同一层写入新的 `transform`，浏览器从当前插值位置改道。
7. **处理冷启动、离开与滚动。** 首次显示先无动画定位到选中项，没有选中项时定位到目标条目，提交起始帧后再淡入并移动。指针离开面板时淡出，图层实例保留。键盘焦点变化走同一层。滚动或重排造成的位移立即对齐，不补滑动。
8. **消除抖动。** 字重变化时预留粗体宽度，或让布局不随状态改变。面板宽度固定，不随指针指向改变。面板带 scale 入场时按布局尺寸换算坐标。
9. **验收。** 按 [验收清单](references/acceptance.md) 逐项检查交互语义、复杂菜单和性能。完成标准：每项有通过结论，或已说明未覆盖。

## 默认参数

| 参数 | 默认值 | 理由 |
| --- | --- | --- |
| 位移与淡入 | `80ms cubic-bezier(0.16, 1, 0.3, 1)` | 起步快，收尾柔 |
| 淡出 | `80ms cubic-bezier(0.4, 0, 1, 1)` | 迅速消失，不留拖尾 |
| 过渡属性 | `transform, opacity` | 不触发布局 |
| 宽高 | 直接赋值，不参与过渡 | 不同高度的条目之间不变形 |
| `prefers-reduced-motion` | 关闭位移过渡，直接定位 | 无障碍 |

这些是默认值，不是硬约束。项目已有 Token 时先用 Token。按真实设备上的体验调参，不用更慢的弹簧惯性代替响应速度。

## 边界条件

- **共享层只画背景。** 点击、选择、焦点、键盘操作和屏幕阅读器描述由菜单组件提供。
- **语义色留在条目上。** 危险操作、禁用、选中和子菜单展开状态保留各自的语义色，共享层只画中性的指针背景。
- **宿主不是 DOM/CSS 时迁移四点原则。** Qt、Flutter 和原生 Windows 没有 CSS transition，迁移共享视觉层、目标位置更新、可中断的短时缓动和输入合帧。API 和属性按宿主重写。
- **减少动态效果优先于动效一致。** 拿不准时去掉动画，保留清晰的焦点反馈。

## 常见误诊

- 把慢弹簧当成丝滑：菜单要的是快速改道，不是长时间拖尾。
- 为每一行做背景过渡，再调时长追平滑：起点错了，改回一个面板一层。
- 把视觉高亮当成选中或可访问性焦点：屏幕阅读器读不到它，键盘会失去语义。
- 只固定面板宽度，行高和字重变化仍会推动布局：抖动源在条目自身尺寸。

## 交付

结束时说明以下各项：

- 共享层的实例数与挂载位置。
- 目标条目的计算方式。
- 最终过渡参数。
- 四种状态的对应关系。
- 减少动态效果的处理。
- 实际验证覆盖范围。

宿主不是 DOM/CSS 时，说明四点原则如何落地。
