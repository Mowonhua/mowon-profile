# 视觉设计路由

根据任务选择所需方法，读取选中的技能并继续完成用户请求。用户无需记住下游技能名称。

## 选择依据

先读取已有的设计约束、相关界面和用户提供的参考。已有 DESIGN.md 或已确认视觉方向时，默认沿用；用户明确要求改变风格时，以本次要求确定变更范围。

用户点名技能时优先采用该技能。若未点名，根据交付物、界面类型和参考选择。能够从上下文判断的常规选择自行完成，只在缺失信息会实质改变设计结果时询问。

同一界面默认采用一套视觉风格。品牌资产与界面实现属于不同交付物时，可以分别选择对应技能；不要把多套字体、颜色、阴影和动效硬规则叠加到同一个界面。

## 路由表

| 任务与已有证据 | 读取的技能 |
|---|---|
| 生成品牌规范板、标志系统、品牌视觉展示图；主要交付物是图像 | [brandkit](../../../.agents/skills/brandkit/SKILL.md) |
| 新建落地页、作品集或编辑型网页，需要依据受众和参考推断合适风格 | [design-taste-frontend](../../../.agents/skills/design-taste-frontend/SKILL.md) |
| 用户要求改进已有网站或应用，主要工作是诊断并修复现有视觉问题 | [redesign-existing-projects](../../../.agents/skills/redesign-existing-projects/SKILL.md) |
| 用户或明确参考要求暖色单色、文档式排版、扁平和克制的界面 | [minimalist-ui](../../../.agents/skills/minimalist-ui/SKILL.md) |
| 用户或明确参考要求工业制图、机械终端、瑞士排版或粗野主义风格 | [industrial-brutalist-ui](../../../.agents/skills/industrial-brutalist-ui/SKILL.md) |
| 用户或明确参考要求具有空间层次、材质与精细微动效的高端网站 | [high-end-visual-design](../../../.agents/skills/high-end-visual-design/SKILL.md) |
| 用户要求以 GSAP 滚动叙事、固定分镜或堆叠动效为核心的营销页面 | [gpt-taste](../../../.agents/skills/gpt-taste/SKILL.md) |

具体风格或动效证据优先于通用的“新建”或“重设计”入口。例如，已有页面明确要改成工业终端风格时，选 industrial-brutalist-ui，不再叠加整套通用重设计技能。普通的“高端”“好看”不足以默认引入玻璃材质、重动效或随机布局。

产品表单、数据表格和多步骤业务界面不走 design-taste-frontend。缺少匹配方法时，依据既有设计系统和用户目标直接完成工作，不强行套用风格。

用户明确需要比较多个视觉方向时，使用 [design-exploration](../../../.agents/skills/design-exploration/SKILL.md)；各方向独立选用风格。已确认方向后需要创建或更新 DESIGN.md 时，使用 [design-creator](../../../.agents/skills/design-creator/SKILL.md)。不要把普通 UI 实现自动扩大为多方案探索或设计系统重建。

Godot 等游戏界面优先遵循该项目 DESIGN.md 和引擎 UI 工作流。仅在用户需要上述品牌资产、网页原型或明确选择相应视觉方法时，才加载表中的网页或品牌技能；网页框架和 CSS 规则不直接套入引擎 UI。

## 读取与执行

1. 从表中选定技能后，通过文件读取工具打开对应 SKILL.md，按其要求只读取本任务需要的参考。不要预读表中所有技能。
2. 开始执行时，用一句话说明采用的技能及其与当前任务的关系，然后继续工作。
3. 下游的风格默认值服从用户明确选择和本项目设计约束；保留现有组件、可访问性与功能要求。示例中的字体、图标、依赖和素材必须按实际环境确认，不假定已安装或已授权外部操作。
4. 若目标文件缺失，检查当前技能安装位置并报告缺失项；仍能依据现有设计约束完成的工作继续执行，不自动安装、复制或启用其他技能。

完成标准：选用的方法匹配用户交付物和已有约束，只加载必要技能，并交付请求的设计或实现及相应验证。
