## 测试治理

项目根目录维护两份测试治理清单，二者必须与当前测试代码保持一致：

- `BEHAVIORS.md`：项目需要长期保证的行为契约，描述“项目应该保证什么”。
- `TEST-DISPOSITION.md`：现有测试与行为契约的对应关系、维护状态与处置结论。

- 任何新增、修改、删除测试的改动，必须在同一次改动中同步更新这两份表；没有同步更新的测试改动视为未完成。
- 新增行为先与既有行为查重，命中则让测试指向既有行为 ID；禁止复用已废弃的行为 ID 与测试 ID。
- 被删除或废弃的条目只更新状态，保留 ID、最终状态与处置原因，不删除行。
- 禁止改动两份表格结构。
- 盘点、处置与登记的具体规则见 `test-behavior-inventory` skill。
