## 功能单元驱动开发

本项目以 `features/*.md` 为系统功能规格的唯一人工维护来源。执行新增功能、功能扩展、缺陷修复、重构和测试清理时，遵循以下规则：

1. 修改前读取 `features/README.md` 和目标模块文档，确定受影响的 `F-ID` 与 `S-ID`。
2. 仅在新增独立系统能力时分配新 `F-ID`；功能职责不变、仅补充特定条件下的预期结果时，只增改行为场景 `S-ID`。
3. 实现与已确认规格冲突时，修复实现代码；仅在需求明确变更时修改规格预期，并记录agent note。
4. 完成代码与测试修改后，同步更新模块文档中的 `功能关系`、`实现` 符号和 `行为场景` 测试节点引用，并运行验证。
5. 仅测试变更只同步当前测试引用，不建立测试台账、审计文件或处置历史。
6. 用户已授权提交且新增功能时，先提交实现与测试，再将该提交 hash 写入功能文档并提交。
7. 需要盘点或精简测试时，遵循 `feature-unit-development` 的测试审查规则。功能视图从当前功能文档生成。
