# 功能单元驱动开发（FUDD）

`features/*.md` 是功能规格与测试关联的唯一人工维护来源。每个模块文档记录当前功能、行为场景、实现符号和测试节点。反向索引与功能视图从这些文档生成。

## 核心概念

- **模块**：按业务或内部职责划分的逻辑分组。
- **功能单元 `F-ID`**：具有独立目的、稳定职责和长期维护价值的系统能力。每个功能只属于一个模块。
- **行为场景 `S-ID`**：功能在指定条件下应产生的结果或应满足的约束。场景可先于实现和测试存在。
- **功能关系**：当前功能主动发出的直接 `依赖` 或 `触发` 关系。
- **实现符号**：功能的主入口和关键实现，写为 `项目相对路径::定位符`。
- **测试节点**：直接断言或观察场景预期的自动化测试，写为 `项目相对路径::测试定位符`。
- **创建提交**：首次实现该功能的提交。作者先提交实现，再将 hash 写入功能文档并提交。

功能 ID 长期稳定。测试直接使用框架定位符，不另行分配 ID。

## 执行流程

1. **确定范围。** 读取 `features/README.md` 和目标模块文档，列出受影响的功能与场景。如果缺少功能文档，仅为当前范围建立最小模型：新建文档时完整复制 [目录模板](assets/features-README-template.md) 与 [模块模板](assets/feature-module-template.md) 到项目 `features/` 目录，仅替换占位项与示例；同时必须将 [项目约束](assets/AGENTS-snippet.md) 全文并入 `AGENTS.md`，已有相同约束时原位更新。
2. **判定规格变化。** 对每项需求使用下表。划分功能或编写场景时，读取 [功能模型规范](references/feature-model.md)。需要系统建模或专项开发规则时，读取 [开发流程](references/development-workflow.md)。完成标准：每项需求都有明确的规格变化，或明确保持规格不变。
3. **更新规格与实现。** 先写明已确认的功能目的和场景预期，再实现代码与测试。实现偏离已确认规格时，修复实现；需求改变时才修改规格。仅测试变更只同步当前测试引用，不产生审计记录。用户只要求讨论或评审时，交付方案后停止。
4. **检查结果。** 使用 [追踪规范](references/traceability.md) 校验文档和引用。运行受影响的测试与项目检查。完成标准：格式无错误，引用已复核，未运行的检查已说明。
5. **交付。** 说明功能变化、验证结果和仍未验证的场景。用户已授权提交且本次新增功能时，按 [创建提交流程](references/feature-model.md#8-创建提交) 登记实现提交。

## 功能模型变更判定

| 条件 | 动作 |
|---|---|
| 现有规格已覆盖，任务仅修复实现、重构或清理测试 | 保留功能与场景 ID，只改代码、测试或引用 |
| 新需求具备独立目的、稳定职责和独立维护价值 | 新建功能单元 |
| 功能目的不变，但输入、输出或适用范围扩大 | 更新功能说明，增改场景 |
| 职责不变，只需补充特定条件下的规则 | 增改场景 |
| 既有功能职责过粗或过细 | 按功能模型规范拆分或合并，记录替代关系 |

## 测试盘点与精简

当任务要求审计覆盖、查找重复测试或精简测试时，读取 [测试审查规则](references/test-review.md)。普通开发无需启动全库盘点。

审查结果直接用于本次修改与回复。只维护当前场景和测试引用，不建立测试台账、审计文件或处置历史。删除测试后，有效场景仍应保留；没有其他测试时填 `-`，并说明验证缺口。

## 功能视图

需要浏览模块、功能详情、功能关系或测试关联缺口时，读取 [视图使用说明](references/visualization.md)。视图只读功能文档。已关联测试不等于测试已通过。

## 模块文档格式

```markdown
## F-MOD-001 功能名称

一句话说明功能目的及输入、输出或状态变化。

创建提交：-

### 功能关系

| 类型 | 功能编号 |
|---|---|
| 依赖 | F-OTH-001 |

### 实现

| 角色 | 代码符号 |
|---|---|
| 主入口 | <源文件路径>::<入口定位符> |

### 行为场景

| 编号 | 类型 | 场景与预期 | 测试 |
|---|---|---|---|
| S-01 | 正常 | 条件满足时产生预期结果 | <测试文件路径>::<测试定位符> |
| S-02 | 异常 | 输入非法时拒绝执行并保持原状态 | - |
```

表头固定。实现角色使用 `主入口` 或 `关键实现`。多个测试用逗号分隔；定位符内的逗号写为 `\,`。无内容的小节直接省略。创建提交未知时填 `-`，不搜索历史实现提交。
